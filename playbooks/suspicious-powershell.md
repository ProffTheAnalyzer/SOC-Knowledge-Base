# Investigating suspicious PowerShell execution

> **Scope:** PowerShell process and script-content investigations. Establish an environmental baseline.

## Trigger

PowerShell execution with unusual parentage, hidden or encoded arguments, script download behavior or unexpected privileged execution.

## Useful telemetry

- Microsoft Defender XDR `DeviceProcessEvents` (process lineage, command line, device and account)
- PowerShell Operational events such as 4104 (when script block logging is configured)
- Windows Security 4688 (when process auditing and command-line collection are enabled)
- Network connections, DNS queries, related file modifications and any EDR prevention alerts

## Investigation steps

1. Identify the device, user, exact process path, command line and process ancestry.
2. Determine whether encoded command-line content is present. Decode **for inspection only**; do not execute the result.
3. Inspect script block or EDR content if logged, focusing on behaviors and destinations.
4. Correlate downloads, file writes, scheduled tasks, service creation and security control changes.
5. Confirm whether it was generated by enterprise management, deployment, backup or approved administrative automation.
6. Scope other devices or users with the same command, hash, destination or signing certificate.

## Benign explanations

System administrators, endpoint management agents, signed automation and application installers may use PowerShell and even encoded commands. One flag is insufficient to classify a process as malicious.

## Outcome

Document confidence, observed behavior, affected scope and investigative gaps. Escalate based on corroborating actions such as persistence, credential access, lateral movement or payload delivery.
